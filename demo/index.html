One section at a time, with native fieldsets and validation. README and API

Generated navigation and section validation

Next validates the current section. Back never does. Enter in a single-line field also advances. The original submit button appears on the final screen, and Start over resets the form and step. With no reference attributes, Start over moves into the full-width footer before Back. Equal Back and Next slots keep progress centered between them, including when Back is hidden. On narrow forms, Start over wraps above the navigation row. 

<form-fieldset-progress>
  <form action="/apply" method="post">
    <fieldset>
      <legend>Contact details</legend>
      <label>Your name
        <input name="name" required
          autocomplete="name" />
      </label>
    </fieldset>
    <fieldset>
      <legend>Delivery address</legend>
      <!-- Labeled, required address fields -->
    </fieldset>
    <fieldset>
      <legend>Review</legend>
      <!-- Review instructions -->
    </fieldset>
    <button type="submit">Send application</button>
    <button type="reset">Start over</button>
  </form>
</form-fieldset-progress>

English custom UI: progress above, buttons below

ID references let you place progress above the form and the buttons below it. Each external button uses form to keep its native form association. Short visible labels default to “Back” and “Next”; longer accessible names identify the destination. This example has no reset button. 

<form-fieldset-progress
  previous-ref="english-back"
  next-ref="english-next"
  progress-ref="english-progress"
  progress-label-ref="english-status">
  <div class="custom-progress">
    <label id="english-status"
      for="english-progress">Application sections</label>
    <progress id="english-progress"
      value="0" max="3"></progress>
  </div>
  <form id="english-application"
    action="/volunteer" method="post">
    <fieldset><legend>Contact</legend>
      <label>Email
        <input name="email" type="email" required />
      </label>
    </fieldset>
    <fieldset><legend>Availability</legend>
      <!-- Labeled hours input, required -->
    </fieldset>
    <fieldset><legend>Review</legend>
      <!-- Review instructions -->
    </fieldset>
  </form>
  <nav class="custom-actions"
    aria-label="Application sections">
    <button id="english-back" type="button"
      form="english-application" hidden>Back</button>
    <button id="english-next" type="button"
      form="english-application" hidden>Next</button>
    <button type="submit"
      form="english-application">Send application</button>
  </nav>
</form-fieldset-progress>

Authored controls and translated labels

Use ID references to own the navigation markup. Text spans with data-fieldset-progress-label preserve decorative icons. Visible and accessible label templates are independently configurable. 

<form-fieldset-progress
  previous-ref="custom-back"
  next-ref="custom-next"
  progress-ref="custom-progress"
  progress-label-ref="custom-status"
  previous-label="Retour : {legend}"
  next-label="Continuer : {legend}"
  progress-label="Étape {current}/{total} : {legend}"
  previous-aria-label="{label}, étape {current}"
  next-aria-label="{label}, étape {current}"
  progress-aria-label="{label}">
  <form>
    <!-- Fieldsets -->
    <nav aria-label="Sections du formulaire">
      <label id="custom-status"
        for="custom-progress">Progression</label>
      <button id="custom-back" type="button">
        <span aria-hidden="true">←</span>
        <span data-fieldset-progress-label>Retour</span>
      </button>
      <progress id="custom-progress"></progress>
      <button id="custom-next" type="button">
        <span data-fieldset-progress-label>Continuer</span>
        <span aria-hidden="true">→</span>
      </button>
      <button type="submit">Envoyer</button>
    </nav>
  </form>
</form-fieldset-progress>

Why step validation should stay on

Keep per-section validation enabled. no-validation delays error feedback and can send people back through sections they thought were finished. Revealing invalid sections at submission is a recovery measure, not a replacement for timely feedback. Avoid this setting unless you provide an equivalent, tested validation workflow.

This exception-only demo shows the recovery path. Try sending without a name: final native validation reveals the first section. 

<form-fieldset-progress no-validation>
  <form>
    <fieldset>
      <legend>Profile</legend>
      <label>Name <input name="name" required /></label>
    </fieldset>
    <fieldset><legend>Review</legend></fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>

Configuration failure and recovery

A missing reference leaves the whole form usable. The error event explains the failure. Repairing the reference restarts enhancement. 

<form-fieldset-progress next-ref="missing">
  <form><!-- Fieldsets and Submit --></form>
</form-fieldset-progress>

// After reporting the setup error:
element.removeAttribute('next-ref');
element.refresh();

No JavaScript and loading fallback

This embedded form loads no module. Before upgrade or while a module loads, the same native form structure remains visible. Submit in this example uses the browser’s local dialog behavior. 

<!-- No module script: every section remains available. -->
<form-fieldset-progress>
  <form method="dialog">
    <fieldset><legend>Contact</legend>…</fieldset>
    <fieldset><legend>Review</legend>…</fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>
