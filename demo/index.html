<form-fieldset-progress>

Turn a form’s fieldsets into steps, with Back, Next, and progress. README and API

Start with a form and fieldsets

Wrap a form in form-fieldset-progress. Each outermost fieldset becomes a step, named by its legend. The component adds the navigation buttons and progress indicator; no configuration attributes are needed.

Fill out Contact details and choose Next to reach Delivery address. Next checks the current section’s fields before advancing. Back returns to the previous section without validating it. On Delivery notes, the form’s submit button replaces Next. These demos show a submission result without sending form data.

Progress shows the current section’s position: Contact details is 1 of 3, so the bar is one-third full. Delivery notes is 3 of 3, so the bar is full. 

<form-fieldset-progress>
  <form action="/apply" method="post">
    <fieldset>
      <legend>Contact details</legend>
      <label>Your name
        <input name="name" required
          autocomplete="name" />
      </label>
      <label>Email
        <input name="email" type="email" required
          autocomplete="email" />
      </label>
    </fieldset>
    <fieldset>
      <legend>Delivery address</legend>
      <label>City
        <input name="city" required
          autocomplete="address-level2" />
      </label>
      <fieldset>
        <legend>Delivery preference</legend>
        <label><input name="delivery" type="radio"
          value="standard" checked /> Standard</label>
        <label><input name="delivery" type="radio"
          value="express" /> Express</label>
      </fieldset>
    </fieldset>
    <fieldset>
      <legend>Delivery notes</legend>
      <label>Delivery notes (optional)
        <textarea name="notes"></textarea>
      </label>
    </fieldset>
    <button type="submit" name="action" value="apply">
      Send application
    </button>
  </form>
</form-fieldset-progress>

Customize the labels

previous-label and next-label change the button text. progress-label changes the text beside progress. Here, {current} is the current section number, {total} is the number of sections, and {legend} is the current section’s legend. 

<form-fieldset-progress
  previous-label="Previous"
  next-label="Continue"
  progress-label="Section {current} of {total}: {legend}">
  <form>
    <fieldset><legend>Contact</legend>
      <label>Name <input name="name" /></label>
    </fieldset>
    <fieldset><legend>Delivery notes</legend>
      <label>Notes <textarea name="notes"></textarea></label>
    </fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>

BYOM: Bring your own markup

The *-ref attributes identify existing elements by ID instead of generating them. This example places progress above the form and buttons below it. previous-ref identifies Back, next-ref identifies Next, and progress-ref and progress-label-ref identify progress and its label.

Each button outside the form uses form="english-application" to associate it with that form. The component updates these controls’ labels and visibility just as it does for generated controls.

Author enhancement-only controls with hidden. The component reveals each control when it is useful after setup succeeds, and restores its authored visibility on disconnect or setup failure. Leave Submit visible so the form works without JavaScript. Hide controls themselves, not an ancestor that also contains the native form. 

<form-fieldset-progress
  previous-ref="english-back"
  next-ref="english-next"
  progress-ref="english-progress"
  progress-label-ref="english-status">
  <div class="custom-progress">
    <label id="english-status"
      for="english-progress" hidden>Application sections</label>
    <progress id="english-progress"
      value="1" max="3" hidden></progress>
  </div>
  <form id="english-application"
    action="/volunteer" method="post">
    <fieldset><legend>Contact</legend>
      <label>Email
        <input name="email" type="email" required />
      </label>
    </fieldset>
    <fieldset><legend>Availability</legend>
      <label>Hours available each week
        <input name="hours" type="number"
          min="1" max="40" required />
      </label>
    </fieldset>
    <fieldset><legend>Experience</legend>
      <label>Relevant experience
        <textarea name="experience"></textarea>
      </label>
    </fieldset>
  </form>
  <nav class="custom-actions"
    aria-label="Application sections">
    <button id="english-back" type="button"
      form="english-application" hidden>Back</button>
    <button id="english-next" type="button"
      form="english-application" hidden>Next</button>
    <button type="submit"
      form="english-application">Send application</button>
  </nav>
</form-fieldset-progress>

Translate labels, maintain button icons

This example combines the label templates and ID references above. The legends, submit button, and navigation templates are in French. Each navigation button uses a data-fieldset-progress-label span so the component updates the text without replacing its arrow.

  progress-label-ref="custom-status"

Add a "review" screen

review-panel adds a final fieldset after the authored sections. Its definition list pairs field labels with the current answers. Selects show option labels; checkbox and radio groups show the selected choices. The review counts as a section in progress, and Submit appears there instead of Next.

Complete Contact and Delivery, then continue to Check your answers. Use Back to change an answer and return: the summary updates each time you enter review. Native validation runs before entering review and again on submission. Passwords, hidden inputs, and disabled controls are omitted. 

<form-fieldset-progress review-panel
  review-label="Check your answers">
  <form>
    <fieldset><legend>Contact</legend>
      <label>Name <input name="name" required /></label>
    </fieldset>
    <fieldset><legend>Delivery</legend>
      <label for="review-country">Country</label>
      <select id="review-country" name="country">
        <option value="uk">United Kingdom</option>
        <option value="ca">Canada</option>
      </select>
      <fieldset><legend>Updates</legend>
        <label><input type="checkbox" name="updates"
          value="email" checked /> Email</label>
        <label><input type="checkbox" name="updates"
          value="sms" /> SMS</label>
      </fieldset>
      <label>Notes <textarea name="notes"></textarea></label>
      <label>Attachments <input type="file" name="files" multiple /></label>
    </fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>

BYORF: Bring your own review fieldset

Use review-ref instead of review-panel to identify an outermost fieldset in the same form. Give it a legend and hidden; the component makes it the final screen and reveals it there. An existing direct dl receives the summary; otherwise one is created. Keep the review read-only, without form controls or links. Your legend supplies its title. 

<form-fieldset-progress review-ref="answers">
  <form>
    <fieldset><legend>Contact</legend>
      <label>Name <input name="name" required /></label>
    </fieldset>
    <fieldset id="answers" hidden>
      <legend>Confirm your details</legend>
      <p>Check these answers before sending.</p>
      <dl></dl>
    </fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>

Listen for section changes

form-fieldset-progress:change fires after the active section changes. Its detail includes previousIndex, stepIndex, stepCount, and the active fieldset element. Indices start at zero.

Enter a name and choose Next, then Back. The output below shows the latest event, using the fieldset’s ID to represent the element. A failed validation does not switch this form’s section or emit a change event. 

<form-fieldset-progress id="events">
  <form>
    <fieldset id="event-contact">
      <legend>Contact</legend>
      <label>Name <input name="name" required /></label>
    </fieldset>
    <fieldset id="event-notes">
      <legend>Delivery notes</legend>
      <label>Notes <textarea name="notes"></textarea></label>
    </fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>
<pre id="section-event">No section change yet.</pre>

const element = document.querySelector('#events');
const output = document.querySelector('#section-event');
element.addEventListener('form-fieldset-progress:change',
  ({ detail }) => {
    output.textContent = JSON.stringify({
      previousIndex: detail.previousIndex,
      stepIndex: detail.stepIndex,
      stepCount: detail.stepCount,
      fieldset: detail.fieldset.id
    }, null, 2);
  });

You can also animate section changes

form-fieldset-progress:beforechange fires after navigation checks, before the section changes. Unlike change, it can be canceled. This example’s script uses that event and the View Transition API to slide between sections while keeping navigation in place. Animation is supplied by the demo script, not a component attribute.

Use Next and Back to see the slide direction change. Uncheck the animation option for immediate navigation. The example also uses immediate navigation when the browser does not support View Transitions or requests reduced motion. The code below shows excerpts from the complete animation script and demo styles.

Form reset is supported too

An authored type="reset" button restores the form controls’ default values and returns to the first section. Enter a name, advance to Delivery notes, and choose Start over to try it.

With no control reference attributes, the component moves this button before Back in the footer. With any control reference attribute, Reset stays where it was authored. The component does not create a Reset button. 

<form-fieldset-progress>
  <form>
    <fieldset><legend>Contact</legend>
      <label>Name
        <input name="name" autocomplete="name" required />
      </label>
    </fieldset>
    <fieldset><legend>Delivery notes</legend>
      <label>Notes <textarea name="notes"></textarea></label>
    </fieldset>
    <button type="submit">Send</button>
    <button type="reset">Start over</button>
  </form>
</form-fieldset-progress>

You can disable per-section validation

I highly recommend keeping per-section validation enabled. If you really want to turn it off, no-validation removes the checks on forward navigation, but does not turn off native submit validation.

Even with this feature disabled, when a field is found to be invalid on submit, the component will display the correct panel automatically so the user can see the issue.

In this example, Next reaches Delivery notes even with an empty Name field. Choosing Send profile then reveals the first section so the browser can report the required field. 

<form-fieldset-progress no-validation>
  <form>
    <fieldset>
      <legend>Profile</legend>
      <label>Name <input name="name" required /></label>
    </fieldset>
    <fieldset><legend>Delivery notes</legend>
      <label>Notes <textarea name="notes"></textarea></label>
    </fieldset>
    <button type="submit">Send</button>
  </form>
</form-fieldset-progress>

Recover from a setup error

Here, next-ref="missing" points to an element that does not exist. Setup emits form-fieldset-progress:error and leaves both fieldsets visible. Repair configuration removes that reference and calls refresh() to try setup again. 

<form-fieldset-progress id="failure" next-ref="missing">
  <form>
    <fieldset><legend>First section</legend>
      <p>This remains visible when setup fails.</p>
    </fieldset>
    <fieldset><legend>Second section</legend>
      <p>So does this section.</p>
    </fieldset>
    <button type="submit">Send example</button>
  </form>
</form-fieldset-progress>

// After reporting the setup error:
const element = document.querySelector('#failure');
element.removeAttribute('next-ref');
element.refresh();
